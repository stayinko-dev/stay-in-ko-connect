# 한국 생활 도움 커뮤니티 웹앱 - 사업화용 메인 구조

## 1) PDF 핵심 요구사항 정리
- 대상: 한국에 온 외국인(여행자, 유학생, 워홀러, 장기체류자)
- 공급: 지역 한국인 도우미(동행/안내/번역 보조)
- 운영: 관리자(검증, 분쟁 처리, 품질 관리)
- 방향: 정보형 커뮤니티 + 유료 도움 매칭을 결합하되, 역할은 분리

## 2) 중복 기능 제거(핵심)
### 제거 기준
- 같은 사용자의 같은 목적을 2개 이상 메뉴가 처리하면 중복으로 간주
- 게시판에서 유료 업무 접수까지 처리하면 커뮤니티와 매칭 경계가 무너짐

### 통합 결과
1. `도움 요청` + `예약/매칭`
- 통합 이유: 둘 다 "유료 현장 도움 성사" 목적
- 결과: 도움 요청 생성 -> 즉시 후보 추천 -> 예약 상태 전환까지 단일 플로우

2. `커뮤니티 후기` + `매칭 후기`
- 통합 이유: 후기 데이터 중복 저장은 신뢰도 왜곡 유발
- 결과: 리뷰 저장은 1개 도메인으로 통합, 화면 노출만 분리

3. `통역 게시판` + `통역 요청`
- 통합 이유: 정보 질의와 유료 요청이 섞여 운영 품질 저하
- 결과: 게시판은 정보 공유만, 통역은 도움 요청 폼으로 진입

## 3) 메인페이지 진입 구조(허브형)
- 도움 요청 (핵심 CTA)
- 매칭/예약
- 커뮤니티
- 검증/안전

원칙: 메인페이지에서 4개 모듈에 모두 바로 접근 가능해야 함.

## 4) MVP 범위(사업성 검증 우선)
- 지역: 서울/수도권
- 언어: 영어 + 한국어
- 서비스: 병원 동행, 관공서 동행, 집보기/이사보조
- KPI: 커뮤니티 MAU보다 유료 매칭 반복률을 우선 지표로 운영

## 5) 법적/운영 원칙
- 도우미는 독립 사업자/프리랜서 구조
- 플랫폼은 결제, 매칭, 평판관리 역할 중심
- 고위험 업무(의료행위, 법률자문, 금융대리)는 범위 제외
- 외국인 데이터 처리 시 PIPA 준수
